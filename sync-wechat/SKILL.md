# 同步公众号文章 Skill

## 触发条件

- 用户输入 `/sync-wechat` 或者明确说"我要同步一篇公众号文章"
- 用户直接把整段公众号正文贴在对话里（如果你判断那是公众号文章，可主动触发本 skill）

## 接收方式

支持两种：

**A. 用户主动粘贴**：用户直接把公众号文章正文贴在对话里。你的任务是从中抽出结构字段。

**B. 用户只发指令 `/sync-wechat`**：你回复：「请把公众号文章正文贴给我（包含：标题 / 发布日期 / 正文 / 原文链接）。」等用户粘贴再开始。

## 字段抽取规则

| 字段 | 必填 | 怎么从用户粘贴的内容里抽出来 |
|------|------|---------------------------|
| `id` | 是 | **自动生成** `wc_<YYYYMMDD>_<NNN>`，例 `wc_20260519_001`。NNN 取今天已有文章的下一个 |
| `tag` | 是 | 从标题/正文推断 1 个中文短分类（4-6 字），如「商务礼仪」「市场观察」「政策解读」「行业速览」「文化常识」「谈判实战」「营销洞察」「物流通关」「投融资」「法务合规」 |
| `title` | 是 | 公众号文章标题 |
| `source` | 是 | 默认 `蓝海中东` |
| `sourceLabel` | 是 | 默认 `公众号：蓝海中东` |
| `publishAt` | 是 | 用户在内容里提到的发布日期（如"2026 年 5 月 19 日"），转成 `YYYY-MM-DD`。没提就用今天日期 |
| `summary` | 是 | **必须从正文前 2-3 段里提炼一段 60-120 字的中文导语**。要包含核心结论或观点；不能只复述标题 |
| `content` | 是 | 正文。**保留段落结构**：段落之间用 `\n\n`（JSON 转义字符串里就是两个 `\n`） |
| `originalUrl` | 否 | 公众号原文链接（用户如果在内容中提到了 `mp.weixin.qq.com/s/...` 的 URL） |

## 执行流程

**Step 1. 解析用户粘贴的内容**

抽取：标题、正文（去掉公众号 footer / 关注引导 / "往期回顾" / 广告位 / 图片占位符）、原文链接、发布日期。

**Step 2. 生成 summary**

如果用户没明确给摘要，自己从正文前 3 段总结一段 80 字左右的中文导语。要求：包含核心论点、不复述标题、不要标题党。

**Step 3. 选 tag**

从上面给的常用 tag 里挑一个最贴合的。

**Step 4. 分配 id**

读 `miniprogram/resources/wechat-articles.ts`，扫描已有数组里今天日期 (`YYYYMMDD`) 下出现的最大序号。下一个就是 NNN+1（首次 001）。

**Step 5. 追加到资源文件**

⚠️ **不要用 `npm run wechat:sync` 命令** —— 那个脚本是覆盖写、会丢现有文章。

直接用 Edit 工具修改 `miniprogram/resources/wechat-articles.ts`：

1. 文件里有一行：`export const WECHAT_ARTICLES: WechatArticle[] = [...]`，里面是单行 JSON 数组
2. 找到数组的开头 `[`，把新文章对象 **插入到第一个位置**（让最新文章排在前面）
3. 文章对象字段顺序固定：`{"id":"...", "tag":"...", "title":"...", "source":"蓝海中东", "sourceLabel":"公众号：蓝海中东", "publishAt":"YYYY-MM-DD", "summary":"...", "content":"段1\n\n段2\n\n段3", "originalUrl":"..."}`
4. content 里的换行用 `\n\n` 字面（JSON 字符串转义），不要真的换行
5. 保持整个 export 语句仍然是一行（脚本读取依赖正则）

**Step 6. 同步构建**

跑 `npm run build:content`，让云导入包 `cloud-import-bundle.json` 同步到最新。

**Step 7. 告诉用户下一步**

输出格式：

```
✅ 已同步「<文章标题>」
✅ id: wc_YYYYMMDD_NNN · tag: <tag>
✅ wechat-articles.ts 已更新，build:content 完成

下一步（约 30 秒）：
1. 微信开发者工具 → 右键 cloudfunctions/contentImporter → 上传并部署
2. 小程序 → 我的 → 设置 → 资源导入（管理员） → **仅导入公众号文章**（最快）

注意：本地 wechat-articles.ts 已经更新，
即使不点云导入，编译后小程序首页发现页也能看到新文章（走本地兜底）。
```

## 多篇一起处理

如果用户一次贴了多篇文章（用 `---` 或明显"第二篇"分隔），逐篇处理：

- 每篇分配独立递增 id
- 全部追加完后只跑一次 `npm run build:content`

## 质量门槛

- summary 必须真摘要、不能是标题复述
- content 必须保留段落结构（`\n\n`），不能糊成一段
- tag 用合理短词，不超过 6 字
- 不要把公众号底部的"长按二维码""点击关注""往期回顾""星标公众号"等无关内容写进 content

## 不要做

- ❌ 不要建议用户去手改 JSON 模板文件
- ❌ 不要跑 `npm run wechat:sync`（会覆盖现有文章）
- ❌ 不要在 content 里嵌图片占位符、公众号样式标签
- ❌ 不要把新文章插在数组末尾——必须插在开头（按时间倒序展示）
